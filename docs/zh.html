一个技能库。
绝不静默覆盖。

本地优先的双向同步：让 Agent Skill、MCP 服务器和规则在 Claude Code、Codex、Gemini CLI、Cursor、VS Code Copilot、DSH 之间保持一致。

SHA-256 状态追踪、逐目标自动备份；发生冲突时退出码 2，而不是悄悄覆盖你的修改。零运行时依赖。

$npx skills add Jack91124/ai-extension-manager
$pip install git+https://github.com/Jack91124/ai-extension-manager

它到底解决什么问题

你为一个工具写的 Skill 困在那个工具里；自己写的同步脚本又是“谁最后改谁赢”。

📚

一个库，按内容寻址

每个资源只在 ~/.ai-extension-manager/library 存一份，带清单、SHA-256 树哈希和版本历史；各工具从库里取副本或链接。

🔁

双向、懂状态

导入可扫描任意工具；分发可推到单个、多个或全部兼容工具。每个目标记录 source_hash + target_hash，下次同步就知道谁改了什么。

🛡️

拒绝覆盖

双方都改了 → 冲突、退出码 2、不写任何东西。用 --on-conflict 显式解决，之前先自动备份目标。

可推理的冲突处理

mtime 不是合并策略。aem 比较三个哈希：库当前哈希、上次同步哈希、目标当前哈希。

$ aem sync --direction distribute --agent claude --resource my-skill
Sync distribute (1 steps)
  claude  skill/my-skill    conflict [C]  both sides changed
summary: { "conflict": 1 }
conflicts were left untouched; use compare_resources.py and resolve them explicitly
  • A 只有库变了 → 安全安装
  • B 只有目标变了 → 作为新版本导入
  • C 双方都变 → 冲突，不写任何文件
  • D 目标被删除 → 重装或解除追踪
  • E 目标目录不存在 → 创建或中止
  • 未纳管的文件永不被触碰

60 秒上手

所有写操作都能先 dry-run，且写之前一定先备份。

# 1. 先看本机各工具装了什么
aem scan

# 2. 把某个工具里的技能拉进中央库
aem import --source ~/.claude/skills/my-skill

# 3. 复制到其他工具（或全部兼容工具）
aem sync --direction distribute --agent codex --agent cursor --resource my-skill

# 4. 证明副本仍与库一致
aem verify --all

# 5. 双方都改过时，先看差异再决定
aem compare --resource my-skill --agent codex
aem sync --direction distribute --agent codex --resource my-skill --on-conflict keep-target

默认安全

无后台进程、无网络请求、无遥测；只动你指定的路径。

密钥不出本机

MCP 配置逐字段合并；env 值在库内脱敏为 ${ENV_VAR}，不会跨工具复制。

危险载荷会被标记

导入时静态扫描（curl | sh、eval、base64 大块、凭据路径），高风险项必须显式 --allow-risk。

可回滚

每次分发与恢复前都先快照目标；aem backup list/restore 可取回任意版本。
