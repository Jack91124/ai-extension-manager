What it actually solves

Skills you write in one tool stay trapped there, and the sync scripts people write instead overwrite whatever changed last.

📚

One library, content-addressed

Every resource lives once under ~/.ai-extension-manager/library with a manifest, SHA-256 tree hash and version history. Agents consume copies or links from it.

🔁

Two-way, state-aware

Import scans any agent; distribute pushes to one, many, or every compatible agent. Each target records source_hash + target_hash so the next sync knows who changed what.

🛡️

Refuses to clobber

Both sides changed → conflict, exit code 2, nothing written. You resolve explicitly with --on-conflict, after automatic per-target backups.

Conflict handling you can reason about

mtime is not a merge strategy. aem compares library hash, last-synced hash and current target hash.

$ aem sync --direction distribute --agent claude --resource my-skill
Sync distribute (1 steps)
  claude  skill/my-skill    conflict [C]  both sides changed
summary: { "conflict": 1 }
conflicts were left untouched; use compare_resources.py and resolve them explicitly
  • A library changed only → safe install
  • B target changed only → import as new version
  • C both changed → conflict, nothing written
  • D target deleted → reinstall or forget
  • E target dir missing → create or abort
  • untracked files are never touched

60-second workflow

Everything is dry-runnable, and every write is preceded by a backup.

# 1. see what is installed where
aem scan

# 2. pull a skill from one tool into the shared library
aem import --source ~/.claude/skills/my-skill

# 3. copy it to any other agent (or all compatible ones)
aem sync --direction distribute --agent codex --agent cursor --resource my-skill

# 4. prove the copies still match the library
aem verify --all

# 5. when both sides moved, look before you leap
aem compare --resource my-skill --agent codex
aem sync --direction distribute --agent codex --resource my-skill --on-conflict keep-target

Safe by default

No daemon, no network calls, no telemetry. It only touches the paths you point it at.

Secrets stay put

MCP configs are merged field-by-field; env values are redacted to ${ENV_VAR} in the library and never synced across tools.

Dangerous payloads flagged

Imports are statically scanned (curl | sh, eval, base64 blobs, credential paths) and high-risk items need explicit --allow-risk.

Reversible

Every distribute and restore snapshots the target first; aem backup list/restore brings any version back.
